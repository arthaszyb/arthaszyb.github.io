# 文章内容优化编辑规范（Content Editing Guide）

> 本规范是批量内容优化的**唯一标准**。你（编辑 agent）会分到一批 `src/content/blog/` 下的 Markdown 文件，逐篇按本规范整理。拿不准的地方一律保守处理并在日志中打 flag，不要停下来提问。

## 0. 总原则

1. **这是博主的个人技术笔记**，不是杂志稿。目标是「干净、可读、诚实」，不是华丽。保持笔记体、第一人称视角。
2. **技术内容神圣不可侵犯**：命令、配置、代码、路径、版本号、输出结果，一个字符都不许改（除了修复明显的迁移断行伪影，见 3.3）。
3. **不编造**：补写的说明只能解释文中已有的东西。不知道就不写。
4. **URL 稳定**：绝不改文件名。frontmatter 中只允许改 `title`、`description`、`tags`、`draft`，以及新增 `origin_url`。`date`、`category`、`source`、`lang` 一律不动。

## 1. 每篇先分类（三选一）

| 类型 | 判定特征 | 处理 |
|---|---|---|
| **repost 转载** | 正文含「版权声明 / 转载 / 原文链接 / 剪辑自 / 已剪辑自」、标题带来源站后缀（CSDN/博客园/知乎/简书/51CTO 等）、正文有抓取 boilerplate（见 3.1）、明显他人署名（"作者：xxx"非博主） | 见 §4 压缩为摘要笔记 |
| **thin 贫瘠** | 清理后正文 < 约 300 字符，通常是一段脚本/几条命令、零说明 | 见 §5 格式化 + 适度补写 |
| **normal 普通** | 其余 | 见 §3 通用整理 |

判定拿不准 repost 时按 normal 处理（宁可少压缩，不可误伤原创）。

**试点批校准补充（必须遵守）**：
- 正文里只要有指向外站原文的链接（CSDN/博客园/51CTO/知乎/个人博客域名），且内容明显是整篇搬运，就按 repost 处理——**不要求出现「版权声明」字样**。该链接必须写入 `origin_url`（这是判定为 repost 后的强制动作，漏写视为不合格）。
- 按 repost 压缩的，日志必须带 `condensed` flag 并记录 before/after 字节数。
- 写文件时**只允许合法 UTF-8 文本**：字节范围、控制字符一律写成文本形式（如 `0x00-0xFF`），绝不写原始字节。完成后如有条件可用 `file <路径>` 自查仍是文本。
- 压缩前先扫一遍正文里的命令/配置行，压缩后逐条核对仍然在场。

## 2. Frontmatter 规则

- `title`：删来源站后缀（如「 - shadowyelling的专栏 - 博客频道 - CSDN.NET」）；修明显病句/错字；保持中文简洁。不要为了「优化」而改一个本来正常的标题。
- `description`：**必须重写**为 1–2 句通顺的中文摘要（40–120 字），说明这篇讲什么、解决什么问题。禁止出现代码片段、命令、原始时间戳、「标签：」之类残渣。这是列表页和搜索引擎看到的门面，认真写。
- `tags`：整理为 2–5 个，**优先从下面的受控词表选**；正文完全不涉及的标签必须删（历史上关键词匹配打了很多错标，尤其 `ssl-tls`、`存储` 被过度使用——文章真讲 TLS/证书/存储才保留）。词表没有但确实核心的概念可新增小写短标签。
  受控词表：`mysql` `redis` `nginx` `apache` `php` `python` `shell-scripting` `docker` `kubernetes` `kvm` `vmware` `linux-admin` `systemd` `selinux` `iptables` `dns` `ssh` `ftp` `nfs` `samba` `rsync` `ssl-tls` `网络排查` `监控告警` `zabbix` `存储` `lvm` `raid` `备份恢复` `mysql-replication` `高可用` `负载均衡` `lvs` `集群` `hadoop` `elasticsearch` `git` `vim` `crontab` `java` `tomcat` `memcached` `cdn` `ldap` `iscsi` `ai-agent` `llm`
- `draft: true` 仅用于：正文实质为空、或清理后完全没有可读价值的（在日志 flag `drafted`）。
- `origin_url`：repost 类填原文链接（从正文里挪出来）；正文找不到链接就不加，在日志 flag `repost-no-url`。

## 3. 通用整理（所有类型都做）

### 3.1 删除抓取/导出垃圾（整行删除）
- 网页抓取元素：`标签：` 后逐行散落的词、`人阅读`、`评论 (0)`、`收藏`、`举报`、`打印`、`阅读目录`、`分类：`、`【大 中 小】`、`收藏本文`、阅读量数字行
- 孤立时间戳行：正文开头的 `2017年7月25日`、`17:52`、`2014-09-25 20:05 2607` 这类
- Evernote/OneNote 痕迹：`已使用 Microsoft OneNote 创建`、星期几+日期回声行
- 版权声明 boilerplate（`版权声明：本文为博主原创文章，未经博主允许不得转载。`——这是被复制文章原作者的声明，删除，链接进 `origin_url`）

### 3.2 结构化
- 连续命令/脚本/配置/输出 → fenced code block，标语言（`bash`/`sql`/`python`/`nginx`/`ini`/`text`，不确定用 `text`）。**命令和输出要还原成它们本来的样子**（多行命令合回一行或保持逻辑行）。
- 内容超过 3 屏且有自然主题段落的 → 加 `##`/`###` 小标题（标题词取自内容本身，别发明新概念）。
- 逐行破碎的句子（迁移伪影：一句话被拆成多行）→ 合并回自然段落。
- 列表体内容 → 规范的 markdown 列表。

### 3.3 迁移伪影修复（这是唯一允许「改」代码的情形）
- `& &` → `&&`、`| |` → `||`（仅当明显是断行拆开的运算符）
- en-dash `–option` → `--option`（命令行选项）
- 词中断行（`Micro\nsoft`）→ 合并
- 修复时若对上下文有任何怀疑，保持原样并 flag `suspect-artifact`

### 3.4 轻度修文（允许但克制）
- 修明显错字、重复词、残句
- 不改变博主用词习惯与句式风格；不做书面语润色；不加语气词和感叹

## 4. repost 转载 → 压缩为摘要笔记

1. 提取原文链接 → `origin_url`（正文中的「剪辑自/原文链接 http…」行删除）
2. 正文重写为**要点笔记体**：
   - 开头 1–2 句：这篇讲什么、什么场景有用（博主视角，如「关于 X 的整理笔记」）
   - 主体：要点用列表/小标题组织，**所有硬信息必须保留**——命令、配置、参数表、对比结论、数字，一个不丢
   - 叙述性、铺垫性、营销性的文字压缩或删除
3. 压缩后长度一般为原文的 30–60%；原文本身很干（全是命令/配置）的可以基本保留只做格式化
4. `origin_url` 缺失的（原文链接找不到）：flag `repost-no-url`，压缩幅度收敛到只删垃圾 + 格式化（因为原文可能已不可考，多保留信息）
5. 日志 flag `condensed`，记录压缩前后字符数

## 5. thin 贫瘠 → 格式化 + 适度补写

1. 先按 §3 整理（脚本进代码块）
2. 在代码块**前**补 1–2 句：这段脚本/命令是做什么的（从代码本身可以确定的事实）
3. 如关键参数值得解释，代码块**后**补 1–2 句参数说明
4. 总补写不超过 4 句。只解释不发挥：不写「背景故事」、不写「总结感悟」、不推测博主当年的场景
5. 代码本身无法确定用途的：只格式化，flag `thin-unclear`

## 6. 特例

- 正文为空或只剩标题回声的：`draft: true`，flag `drafted`
- `<!-- image lost in migration: ... -->` 注释：保留原样，不要删
- 正文中确属文章主题的「版权/转载」字样（比如文章本身在讨论版权）：保留
- 2025 年的两篇手写文章（llm-xuexi-biji、zhongji-debug-jishi）如在批内：跳过，flag `skipped-clean`

## 7. 每篇输出日志

处理完一篇，向你的批次日志文件（任务指令中给出的路径）追加一行 JSON：

```json
{"file":"2016-03-01-qianxi-http-post-get.md","type":"repost","actions":["boilerplate-removed","condensed","desc-rewritten","tags: python,网络排查","origin_url-added"],"flags":[],"before_bytes":5200,"after_bytes":2400}
```

flags 可选值：`condensed` `repost-no-url` `thin-unclear` `suspect-artifact` `drafted` `skipped-clean` `needs-human`（任何拿不准的情况都可以打 `needs-human` 并附 `"note"` 说明）。

## 8. 自查清单（每篇完成前过一遍）

- [ ] frontmatter 只动了允许的字段，YAML 语法合法（描述含冒号要加引号）
- [ ] description 是通顺中文，无代码/时间戳残渣
- [ ] 正文无 §3.1 列的任何垃圾模式
- [ ] 所有命令/配置在代码块里，语言标注了
- [ ] 没有删掉任何命令、配置、参数、数字结论（repost 压缩也一样）
- [ ] 补写的句子（如有）全部是可从内容本身确定的事实
